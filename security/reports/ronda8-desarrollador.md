## 4. Pospuesto o rechazado (resumen)

- **`response_model` opcional por acción** (§3.10): pospuesto. Por ahora el stub lo documenta.
- **`description` multidioma** (UX-61): rechazado por coste y compatibilidad del YAML.
- **Quitar los IDs de informe de los comentarios** al crear proyectos (UX-63): rechazado por riesgo.
- **SEC-34 en SQLite:** se acepta el exceso. PostgreSQL, que es el entorno de producción, queda serializado.
- **SEC-36:** con `/tmp` compartido fuera de Docker, otro usuario aún puede *crear antes* el fichero de latido (DoS del healthcheck, que fuera de Docker no se usa). Mitigación documentada: `JOBS_HEARTBEAT_FILE` en un directorio propio.
- **SEC-33 con `thread`:** el hilo vencido sigue ejecutándose hasta acabar (Python no puede matarlo). Ya no se reintenta; para cortar de verdad, usa `executor: process`.

## 6. Notas para la siguiente ronda

- **Compatibilidad del código generado:**
  - los alias de permisos de las acciones cambian de nombre (`CanX` → `CanAction_x`);
  - toda acción tiene ahora esquema de entrada (antes, una acción sin `fields` ignoraba el cuerpo; ahora da 422 con campos desconocidos);
  - los stubs de tareas thread/process nuevos reciben `ctx`;
  - regenerar con `--force` aplica todo esto, y los hooks y tareas existentes no se tocan.
- **`new_api.py`** exige que la plantilla esté commiteada: hoy el repo tiene cambios de las rondas 7 y 8 sin commit (`apigen/docs.py` y `scripts/` sin versionar), así que habrá que hacer commit antes de usarlo.
